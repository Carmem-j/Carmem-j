1. Visão Geral

A Empresa X mantinha um widget legado de gráficos temporais usado em ambientes de clientes de fracking, originalmente desenvolvido para outro domínio. Por ter sido “reaproveitado” fora do contexto original, acumulava problemas de manutenção, alto custo técnico e isolamento dos demais widgets da plataforma, apesar de a estrutura geral ser modular. O projeto teve como objetivo substituir esse widget por uma solução no-code integrada ao núcleo da plataforma, dando autonomia ao usuário e abrindo espaço para escalar features além do setor de fracking.

2. Entendimento do Problema

O widget legado apresentava gaps sérios:

  • Era caro de manter e corrigir bugs (estrutura técnica inadequada)
  • Não se comunicava com os outros widgets da plataforma (PTZ: pan, tilt, zoom, que não funcionava em conjunto)
  • Acumulava features que já existiam no dashboard, gerando redundância
  • Por usar uma linguagem de programação interna da empresa, exigia que o usuário recorresse a um cientista de dados para qualquer edição via código

Objetivos do projeto:

  • Integrar features de visualização de dados ao principal widget no-code de dados temporais da plataforma (o widget de referência era híbrido e alguns recursos só existiam via código)
  • Substituir completamente o widget legado, dada sua complexidade técnica e alto custo
  • Permitir que features originárias do widget de fracking pudessem ser usadas em outros mercados

3. Pesquisa & Descoberta

A construção do mapa de stakeholders no início do processo foi essencial para identificar todos os atores relevantes e agrupá-los conforme a tríade do projeto: tecnologia, negócios ou usuário.

Os dois maiores desafios da fase de discovery:

1. Mediação entre os três pilares.

A plataforma na época não suportava uma estrutura de dados ideal, um dos principais gaps era técnico. A priorização precisou ser cuidadosa: pequenas entregas faseadas para adaptar o usuário à transição, mas começando pelas features tecnicamente viáveis e mais urgentes para os usuários.

2. Aprendizado de domínio.

Até então, eu projetava soluções genéricas para qualquer mercado ou para o domínio de drilling (extração tradicional de Óleo & Gás). O projeto trazia uma iniciativa para o domínio de fracking, com método de extração distinto: processos diferentes, jornadas de usuário diferentes, estrutura de dados completamente diferente. O uso de IA generativa foi essencial para acelerar a imersão no novo domínio, otimizar transcrições de reuniões e organizar a documentação.

4. Decisões Estratégicas

O ponto forte da execução foi a priorização estruturada acordada com todas as partes, respeitando o ritmo de adaptação técnica da plataforma (estrutura de dados ainda não suportada nativamente, negociada cross-squads) sem perder de vista a necessidade do usuário.

A divisão de entregas foi definida em sessões de priorização que facilitei usando o framework MoSCoW com diferentes grupos de stakeholders:

  • Primeira entrega: features must have, viáveis tecnicamente no momento, utilizáveis por clientes de outros domínios além de fracking
  • Segunda entrega: features must have, viáveis tecnicamente, voltadas exclusivamente ao domínio de fracking
  • Terceira entrega em diante: ainda em negociação

5. Resultados / Impacto

Os ganhos vão além da substituição de um widget caro de manter:

  • Com o widget no-code de dados temporais, os usuários ganham autonomia para criar e editar visualizações sem depender de um cientista de dados para cada edição via código
  • O novo widget é sincronizado com os demais widgets de dados temporais da plataforma, usuários de fracking ganham acesso a uma gama de ferramentas de visualização, análise e navegação que antes eram isoladas
  • O esforço em tornar a solução genérica o suficiente permitiu encontrar um caso de uso de alta aderência dentro de um produto interno de drilling (mapeamento de KPIs)

Métricas estimadas (baseadas em observação direta e em medidas aproximadas, pois não havia infraestrutura formal de medição na época):

~20% redução de espaço vertical Estimativa para um dashboard de monitoramento de sondas (modular, montado pelo próprio usuário): com um widget de série temporal (~190px), um de estado da sonda (~60px) e ~10px de espaçamento por sonda, a Top Band (~16px) no lugar do segundo reduziria cada trecho de ~260px para ~206px. Uma das principais conquistas de impacto além do escopo original de fracking.
>60% da receita da empresa Drilling era a maior fonte de receita, seguido de fracking. Escalar features para ambos significou cobrir as duas maiores fontes de receita simultaneamente.

Features genéricas que influenciaram as métricas

As features da primeira entrega que mais se destacaram nas reuniões e apresentações cross-squad, e que também entregaram valor para os dois mercados responsáveis pela maior fonte de receita da empresa, foram dois recursos complementares de visualização de dados que compunham a aba “Data Tags”: Top Band e Flags. A primeira versão de teste era específica para fracking, mas já tinha estrutura para ser genérica para qualquer mercado, o que a tornava ainda mais interessante.

O maior benefício foi a redução de espaço vertical. Em dashboards de monitoramento do estado de sondas (mercado de drilling), cada sonda era monitorada por um widget próprio. A Top Band permite exibir os estados (stages) de um poço dentro de um widget de série temporal, combinando duas visualizações de dados ao mesmo tempo (veja a imagem abaixo). Assim, haveria um widget a menos por sonda no dashboard.

6. Aprendizados

O projeto consolidou três aprendizados centrais:

  • Priorização cross-squads e em fases é viável mesmo quando a plataforma tem limitações técnicas, basta que cada entrega respeite os critérios mínimos de viabilidade e urgência do usuário
  • MoSCoW funciona em alto nível com múltiplos grupos quando facilitado com clareza sobre os trade-offs envolvidos
  • IA generativa pode ser uma aliada poderosa em discovery para acelerar a imersão em domínios novos, organizar documentação e otimizar transcrições, desde que o profissional mantenha o senso crítico sobre o que é insight real e o que é alucinação
